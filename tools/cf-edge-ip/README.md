# CF 边缘 IP 优选

给 v2rayN 用的辅助脚本：把「Cloudflare 套壳节点」的域名换成实测可用的固定边缘 IP，
解决 CF 节点**间歇性断流**。

## 问题

套 CF 的节点（Cloudflare Worker 自建、各种 CDN 中转）写的是域名，v2rayN 每次连接
都要重新解析。而 CF 的 DNS 每次只返回**一个**轮换 IP，这些 IP 质量参差——其中一部分
会在 **TLS 握手阶段静默丢包**：不报错、不断连，只是卡 3-4 秒然后超时。

表现为「能用一阵，突然断流，换节点又好一阵」，用户无法提前知道这次分到的是好 IP
还是坏 IP。

同一个 CF 网段内差异极大，**无法从 IP 段推断，只能逐个实测**：

```
104.16.0.0/13  ->  104.17.128.76    3/3    520ms   OK
104.16.0.0/13  ->  104.22.5.163     0/3    --      完全不通
```

## 用法

1. 把 `cfip.ps1` 和 `cfip.bat` 复制到 **v2rayN 安装目录**（和 `v2rayN.exe` 放一起）
2. 在 v2rayN 里选中要优选的节点（脚本会读它当前生效的配置）
3. 双击 `cfip.bat`
4. 等它跑完（约 1-2 分钟）
5. 切到 v2rayN，点节点列表空白处，`Ctrl+V` 导入
6. 双击导入的节点切换过去

脚本是**新增**节点，不会删除或覆盖已有节点。

> 脚本必须放在 v2rayN 安装目录里，因为它要从 `binConfigs\config.json` 读当前节点参数。
> 放在别处时脚本会尝试从运行中的 v2rayN 进程推断目录。

## 可调参数

脚本开头三行：

```powershell
$Tries      = 3     # 每个 IP 测几次
$TimeoutSec = 5     # 单次超时（秒），线路差可以调到 8
$Top        = 3     # 生成几个节点
```

## 原理

### 1. 读当前节点

从 `binConfigs\config.json` 找到真正的代理出站（优先 `tag=fragment-proxy`），提取：

- 协议、服务器地址、端口、凭据
- SNI / fingerprint / ECH / ALPN
- 传输方式与参数（host / path / serviceName / mode / headerType）

兼容三种出站写法：`vnext` 数组、`servers` 数组、扁平写法。
兼容 `ws / httpupgrade / xhttp / grpc / tcp(raw) / kcp` 各种传输。
Reality 节点也能处理，但测速结果仅供参考（Reality 握手需要特定客户端）。

### 2. 收集候选 IP

| 来源 | 说明 |
|---|---|
| 内置列表 | 实测通过的固定 IP，兜底用 |
| 金矿段采样 | `104.17.128.0/18` 实测命中率最高，重点采样 |
| 官方段探索 | 拉 `https://www.cloudflare.com/ips-v4`，每段随机采样一个（连拉 3 次，失败则跳过） |
| 域名解析 | 当前节点域名此刻解析出的 IP |

### 3. 直连测速

用 `curl --resolve` 把域名指向候选 IP，再加 `--noproxy '*'` **绕开一切代理**：

```powershell
curl.exe -sS -k --ssl-no-revoke --noproxy '*' --connect-timeout 3 `
    --resolve "${sni}:${port}:${ip}" `
    --max-time $TimeoutSec -o NUL -w "%{http_code};%{time_appconnect};%{time_total}" `
    "https://${sni}:${port}${path}"
```

**判据必须同时满足两条**：

1. TLS 握手成功（`time_appconnect > 0`）
2. **HTTP 响应真的回来**（`http_code != 000`）

只看第 1 条会漏掉最要命的情况——**握手过了但数据卡住**，这正是断流的典型表现。
对比（同一批 IP，只改判据）：

| IP | 只看握手 | 握手 + 响应 |
|---|---|---|
| `104.18.11.118` | 3/3 · 2095ms · 可用 | **1/3 · 淘汰** |
| `104.16.51.41` | 3/3 · 4329ms · 可用 | **1/3 · 淘汰** |

只认 3/3 全过，能通但慢的一律淘汰。

### 4. 生成链接

把选中的 IP 拼成 `vless://` / `trojan://` / `vmess://` 链接，备注带上延迟，
写入剪贴板。v2rayN 的批量导入按换行拆分，多行链接可以一次粘贴导入。

## 支持范围

| 协议 | 支持 | ECH |
|---|---|---|
| trojan | 是 | 保留 |
| vless | 是 | 保留 |
| vmess | 是 | **链接格式没有该字段，导入后会丢失** |
| 其他 | 明确报错，不崩溃 | - |

## 关于系统代理

**开不开都不影响脚本。** 它用 `--resolve` + `--noproxy '*'` 直连 CF 边缘，
刻意绕开代理——走代理测出来的是代理自己，不是这条线路的真实质量。

反过来说，**代理挂着的时候脚本照样能跑**，这反而是它的用处。

## 注意事项

- **会覆盖剪贴板**，跑之前先把重要内容复制走
- 跑多次会积累多条节点，旧的自己删
- 内置 IP 和「金矿段」的判断基于特定时间、特定运营商的实测，换网络后需要重新验证
- 测速只验证到 TLS + HTTP 层，不保证节点在 v2rayN 里一定能翻墙（还需要协议层配对）

## 依赖

- Windows 10 1803 以上（自带 `curl.exe`）
- PowerShell 5.1（系统自带）
- 运行中的 v2rayN（要读它生成的 `binConfigs\config.json`）
